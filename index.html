SMW AI — how it works

  • Sees the whole screen (js/perception.js): full 256×224 core framebuffer. Tracks Mario vs Luigi by cap color + face (red/green + skin continuity), classifies enemies by color signature (goomba, rex, koopa, spiny, piranha, buzzy, shell, flyer), spots the key (big yellow), keyhole (dark slot), goal gate (tall posts), walls/pits in player-anchored boxes, and stomp popups (white bursts).
  • Learns across playthroughs (js/learning.js): linear Q-learner (13 features × 12 actions: arrow × run(Y) × jump(B)), TD-updated from shaped rewards (mario-ai's +1/+0.5/−1/−1.5 table rescaled, stomp +0.5, key/keyhole bonuses, exits +3/+5, death −3). Starts from the run-right prior, which decays as experience grows.
  • Learns from deaths: each death records level + world-X + cause (enemy type / pit / fall); death spots form a per-level danger map the policy treats as a caution feature with anticipatory penalty. Repeat-death counter shows whether it stops dying in the same place.
  • Hunts exits: goal gates count as normal exits; key-then-keyhole-then-transition counts as a secret exit. Per-level exit checklist + totals in the status panel; brain persists in localStorage (export/import/reset below).
  • Roots in aleju/mario-ai (MIT): same ε-greedy 0.8→0.1 schedule, same reward spirit, same raw-pixels-only rule. The Torch DQN + lsnes + CUDA stack can't run in a browser (see js/mario-ai.js).
