# Plan: Skate-3-style animation for the rigged skater

## Verdict on your complaint (verified by code audit, no changes made)

You're right about what you see. The GLB **does** contain a real 54-joint skeleton and a real 3.7s kickflip clip — but outside the ~0.6s flip window the character is effectively frozen:

- `poseRig` pins the mixer at `stanceT=0.8` every non-flip frame and lerps the whole skeleton between two near-identical standing snapshots (`stance`/`crouch`), with constant factors in most states.
- Push has no leg swing (only a ±0.22 whole-body pump), grab/carve/powerslide add no bone motion at all (container lean only), the sampled `land` pose is never used, and 6/7 board node names are wrong (`wheel_back_right` vs actual `wheel back right`), so wheels/trucks never bind.
- The only genuinely animated state today is kickflip/shove. Everything else is a statue that leans.

## Approach: hybrid, procedural-first, zero new assets

Keep the authored kickflip window (it's good mocap). Replace the whole-pose lerp with a **per-bone procedural state machine** whose axes are learned from the clip's own pose deltas (crouch−stance, launch−stance), so joints bend the anatomically-correct way. No new downloads: ~200 lines, 0 bytes, 0 license risk, trivial CPU (~22 quat multiplies/frame). Do NOT fetch extra mocap now — same-author retargeting is unverified, heavy (~5–10MB/model), and unnecessary for 80% of Skate-3 readability.

## Per-state spec (drivers read existing `P.*`, no physics changes)

| State | Trigger | Motion |
|---|---|---|
| idle | grounded, speed<0.8 | breath: `spine_02.rx 0.02·sin(t·2.1)`, pelvis bob ±0.008, arm micro-sway, head look-around |
| push | `W`/pad.push, speed>0.5 | stride oscillator `P.stride += dt·(5+speed·0.9)`; push leg `thigh_r.rx −0.5+0.65·sin(ph)`, calf/foot follow-through; stance leg holds flex; arms counter-swing; pelvis bob |
| charge | `P.charging` | spring to crouch: pelvis −0.12·norm, thighs +0.5, calves +0.6, spine +0.25, arms back |
| air | airborne | tuck: thighs +0.9, calves +1.1, arms out `rz ∓1.15` |
| grab | `P.grab` in air | NEW distinct reaches: Q=Melon (front arm down-in), E=Indy (mirror), U=Nose (arm forward + spine); tuck forced ≥0.8 |
| flip/shove | `P.flipSpeed/shove ≠ 0` | authored window 1.85→3.05s for legs+Deck; procedural upper-body override so torso stays tucked |
| land | `P.absorb>0` | wire the dead `land` pose: snap-to-land, decay to stance 0.35s; pelvis dip + knee spike; wobble windmill on `P.wobble` |
| grind | `P.grind` | deep bend, 50-50 split stance, spine yaw to rail, arms windmill with `balanceErr`; Deck locked flat |
| carve/powerslide | `|yawRate|>0.3` / new `P.powerslide` flag | spine roll ∓0.35, pelvis yaw, head looks through turn; slide = exaggerated + wide arms + sparks |
| bail | `P.bailT>0` | sprawl→kneel timeline: arms up, legs split, spine arch, container tip (keep, improve) |

## Structural changes (`game.js` only, + attribution-safe)

1. **Load block (~300-369):** fix board names to spaced versions + add `Empty`, `Empty.001`, `ball_l/r_human`; store per-bone base pos/quat + crouch/launch delta quats for learned axes; keep root-strip + scale/grounding as-is.
2. **Replace `blendBones` whole-pose lerp** with `addEuler`/`addPos` additive helpers (`bone.quaternion = baseQuat · offset`). Keep function for base stance↔crouch only.
3. **Rewrite `poseRig` into 4 ordered phases** (same signature): (1) one `mixer.update` first — flip window, else stance base; (2) legs; (3) spine/arms/head; (4) board flat-lock (`Deck/Empty*` slerp to base when not flipping) + container lean/squash. Never write bones before the mixer update.
4. **`step()`:** move `P.stride` advance next to `P.pushT`; expose `P.powerslide`, `P.grabKind` (Q/E/U), `P.airH`. No other physics edits.
5. **Fallback capsule rider untouched** — still the load-failure path.
6. No new assets; keep `models/skater.glb.attribution.json` + HUD credit. No `index.html`/`pad.js` runtime changes (optionally map LB/RB to grabKind — game reads held keys, no pad change needed).

## Risks → mitigations

- Wrong bone-axis signs → calibrate from sampled deltas + existing `__rig.setT` prober, tune in-browser before hardening.
- Mixer-vs-manual fighting → strict order: single mixer update first, procedurals after; flip-exit 0.1s blend to avoid pops.
- Deck residual spin → flat-lock branch when not flipping.
- Load failure/offline → fallback path untouched; test with blocked model URL.
- Perf → no per-frame allocations (reuse temps), fingers excluded; gate ≥28fps on SwiftShader.
